# 第一轮生产化加固

本轮完成 worktree 成果保护、协作文件写入保护、权限判定调整、文件历史恢复与 CI。现有会话、权限模式和工具接口保持兼容；以下行为有意收紧。

## Worktree 成果保护

- 新建分支使用 `git worktree add -b`。同名分支存在时返回错误，绝不重置它。
- 创建基线与初始化后的忽略文件指纹保存到 `.QiCode/worktree-state/<slug>.json`。重新进入沿用原基线。
- 清理统一读取保存的基线，不采用模型传入的 `head_commit`。存在未提交、未跟踪文件、新提交、变动的忽略文件、独立 node_modules 或无法核验的状态时保留 worktree 与分支。
- Git 删除不使用 `--force` 和 `-D`；worktree 删除失败时不继续删分支。
- 旧 worktree 缺少基线时允许进入，但禁用自动清理。保留下来的成果可先提交、比较与合并，人工确认后再使用 Git 清理。

## 文件写入与并发

- ReadFile 记录内容哈希。Agent 覆盖已有文件前必须读取；发现版本过期时返回错误，要求重新读取并合并。
- 文件工具通过规范路径识别别名，并使用本机临时目录中的排他锁，在合作的 QiCode 进程之间串行化同文件写入。
- 写入使用同目录临时文件、刷盘和原子替换；替换前再次核验版本。失败时保留原文件，替换时保留已有文件权限位。
- 写入取消或备份失败时不修改文件。可确认拥有者已退出的遗留锁能够回收；活跃进程的锁不会被按时间强行抢占。
- 锁是协作机制。编辑器、Shell、Git 和其他程序不参与锁协议；它们仍可能与 QiCode 竞争。Bash 改动不纳入文件工具的历史回滚。

## 权限变化

- 危险命令、路径检查和显式 deny 优先于只读命令快速放行、会话允许、Plan 文件豁免和 bypassPermissions。
- 任一级别匹配的 deny 都优先于 allow。已存在的通配规则仍保留通配语义。
- 新增永久审批保存完整内容并标记 `exact: true`，不再截断命令或自动追加 `*`。
- 自动放行拒绝多行命令、重定向、变量展开与更多 Shell 元字符。带写变体的 `date`、`file` 和可能触发输出文件或外部程序的 Git 子命令改走审批。
- 本轮没有实现操作系统级命令沙箱；Shell 执行仍需用户审批与现有启发式策略。

## 崩溃恢复与回滚

- 项目文件的备份、待完成写入、预期写后哈希、检查点和版本索引持久化到 `.QiCode/file-history/<session>/index.json`。
- 文件工具先保存备份和索引，再修改文件。`/resume` 恢复会话时同时加载文件历史；`/rewind` 可列出完成或中断的检查点。
- 备份先刷盘再保存索引；崩溃留下的孤立备份继续保留，后续写入使用新的版本号。
- 回滚一个旧检查点会包含后续检查点的修改。恢复前先验证所有备份与目标文件；发现用户后续修改、跨轮次插入的外部修改或备份损坏时拒绝覆盖。
- 回滚与写工具共享文件锁。回滚并非跨多个文件的数据库事务；中途 I/O 错误时保留检查点，已恢复到原状态的文件允许再次恢复。
- 旧版本仅留下备份文件、没有索引的历史无法自动重建；这些文件不会被自动删除。
- JSONL 会话追加使用排他锁与刷盘。若上次崩溃留下不完整尾记录，先将原始尾部保存为 `.corrupt-*` 文件，再修复并追加。
- 本轮恢复的是会话记录与文件历史，不会自动重新执行崩溃时的 Shell 命令或后台任务。
- `.QiCode` 与 `.qicode` 的运行状态均默认忽略，保留现有配置示例的提交例外，避免 Linux 上的小写会话目录被意外提交。

## 验证与 CI

本地检查：

```bash
pnpm typecheck
pnpm test
pnpm build
```

`.github/workflows/ci.yml` 在 push 与 pull_request 时对 Windows、Linux、macOS 和 Node 22 / 24 执行锁文件安装、类型检查、测试、构建及构建入口导入检查。安装使用 npm 官方 registry，工作流只申请仓库读取权限。

工作流参考官方 [checkout](https://github.com/actions/checkout/tree/v6)、[setup-node](https://github.com/actions/setup-node/tree/v6) 和 [pnpm/action-setup](https://github.com/pnpm/action-setup/tree/v4) 用法。跨平台结果以远端 CI 实际执行为准；本机 Windows 检查不能替代它。
