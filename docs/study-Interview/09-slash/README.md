# 第九章 Interview：如何讲 Slash 命令体系

## 简历描述

我把终端 Agent 的硬编码 Slash 命令重构为可扩展的命令体系：Registry 统一管理命令名、别名、描述和执行类型；输入层提供补全；App dispatcher 按 local、local_ui、prompt 三类分流，保证本地查询不消耗 token，而 prompt 命令仍复用正常的会话持久化和 Agent 执行链路。

## 高频问题

### 为什么不能在 `App.submit()` 里继续加 `if (command === ...)`？

早期命令少时可以，但帮助列表、别名、冲突检测、补全和后续模块扩展都会形成多份命令清单。Registry 让它们读取同一份事实来源，新增命令不再需要在多个地方同步维护字符串。

### `local`、`local_ui`、`prompt` 的边界是什么？

`local` 只读本地状态，例如 `/status`；`local_ui` 改变客户端状态，例如 `/clear`、`/resume`；`prompt` 把命令转换成真实用户任务，例如 `/review`。最重要的约束是：只有 `prompt` 才能进入 Agent 和 LLM。

### `/review` 为什么不直接由本地函数执行 Git？

它的目标是让 Agent 使用已有工具收集改动并判断风险，本地命令只负责构造任务。这样 Git 操作仍经过工具注册、权限检查和 Agent 循环，不会出现 Slash 命令绕过第五章权限链。

### 为什么 prompt 命令要调用 `submit(prompt, true)`？

它必须走普通消息的 Conversation、JSONL、超时、权限、文件快照和后台记忆提取路径。`true` 用来阻止二次 Slash 解析，否则一个自定义命令正文如果以 `/` 开头，会被误当作另一条本地命令。

### 为什么本地命令结果不进入 Conversation？

`/help`、`/status` 是用户对客户端的查询，不是模型完成任务所需的上下文。把它们塞进 Conversation 会污染后续请求，还会错误写入 session。当前 TUI 使用本地通知区展示它们；真正需要影响模型行为的 `/plan`、`/do` 才写 reminder。

### Registry 如何避免命令冲突？

维护主名 Map 和别名 Map。注册时检查主名重复、主名撞别名、新别名撞主名、新别名重复。冲突在启动阶段就抛出或产生诊断，避免后注册者静默覆盖前者。

### 为什么用户命令用 Markdown，而不是配置 YAML？

命令正文本质上是给模型的 prompt，Markdown 对长文本和代码块更自然；frontmatter 只承载描述、别名和参数提示。正文与元数据分层后，加载器能在元数据损坏时退化为整文件正文。

### 为什么不直接安装 Fuse.js？

当前命令数量很小，项目也没有该依赖。实现了一个受限的本地评分：名称最高、别名其次、描述最低，并只在精确和前缀匹配之后作为兜底。生产环境若命令数量、语言匹配和排序需求显著增长，再替换为成熟库并做依赖审查更合理。

## 可主动说的局限

- 自定义命令不支持热加载，修改文件后需重启。
- 使用频次是本机文件，没有跨机器同步和锁机制。
- 扩展动作接口已存在，但第十、十三、十四章尚未接入真实模块。
- 自动化验证了补全候选和分发；真实终端下 ESC、Tab、窄窗口视觉效果仍需手工冒烟。
