## 1. 背景

经过前六章，QiCode 已能持续调用模型、执行本地与 MCP 工具并维护多轮历史。随着会话增长，
完整历史、工具结果和稳定提示会共同占用模型上下文。大文件读取、长命令输出或多轮工具调用
会迅速耗尽窗口，最终触发上下文过长错误，导致 Agent 无法继续工作。

本章建立上下文预算、工具结果降载、自动压缩、紧急恢复和压缩边界能力，使长任务可以在有限
上下文窗口内继续执行。

## 2. 阶段目标

1. 在每轮请求前估算上下文占用并应用预算策略。
2. 把超大工具结果保存到 `.qicode/tool_results/`，请求中只保留可定位的预览。
3. 对较旧工具结果进行稳定裁剪，避免同一结果在不同轮次反复变化。
4. 接近窗口阈值时自动把旧历史压缩为摘要，保留最近消息原文。
5. 收到 `ContextTooLongError` 时执行一次紧急压缩并恢复当前任务。
6. 支持 `/compact` 手动压缩，并记录可供后续会话恢复使用的压缩边界。

## 3. 本阶段范围

### 3.1 包含

- token 近似估算与上下文阈值判定。
- 单条工具结果大小上限、总工具结果预算和旧结果裁剪。
- 工具结果原文安全落盘与预览替换。
- 会话级替换决策账本。
- 自动压缩、手动压缩和上下文过长恢复。
- 恢复附件：近期文件、活动 Skill 和可用工具摘要。
- 压缩边界的最小持久化接口。
- 用量锚点和重复压缩熔断。

### 3.2 不包含

- 向量数据库或语义检索。
- 跨项目共享上下文。
- 自动选择历史会话并恢复；完整 `/resume` 体验由第 08 章实现。
- 长期记忆提取；由第 08 章实现。
- 修改 Provider 的六个配置字段。
- 无限重试；紧急压缩最多按明确上限执行。

## 4. 核心概念

### 4.1 API 历史与完整历史

- 完整历史保留当前进程内的真实消息和完整工具结果。
- API 历史是发送给模型的临时副本，可用预览、裁剪或摘要替换大内容。
- 预算处理不得原地破坏完整历史。

### 4.2 工具结果降载

- 单条结果超过阈值时，把原文写入 `.qicode/tool_results/<toolUseId>`。
- API 历史中的结果替换为 `<persisted-output>` 预览，包含原始大小、绝对路径和有限前缀。
- 同一 `toolUseId` 在同一 Agent 生命周期内必须得到稳定的替换决策和替换文本。
- 路径必须限制在当前工作区的 `.qicode/tool_results/` 下，标识符必须经过安全校验。

### 4.3 会话压缩

- 压缩选择较旧历史生成结构化摘要，并原样保留最近若干消息。
- 摘要请求不携带工具定义，避免模型在压缩阶段发起工具调用。
- 压缩后的历史以“摘要消息 + 最近原文”替换当前会话的 API 历史基础。
- 摘要必须覆盖目标、已完成工作、关键决策、文件变更、未解决问题和下一步。

## 5. 功能需求

### F1. 上下文预算

- Agent 每轮请求前基于当前 Provider 的上下文能力和输出预留计算可用输入预算。
- 上下文窗口不再通过新增 Provider 配置字段表达；由 Provider 能力或应用级模型能力表提供。
- 估算函数必须确定、快速，并明确属于近似值而非真实 tokenizer 结果。

### F2. 工具结果单条上限

- 超过单条阈值的结果必须落盘并替换为预览。
- 小于阈值的结果保持原文。
- 文件已存在时不得覆盖不同内容；写入失败不能被静默忽略。

### F3. 工具结果总预算

- 单轮所有工具结果超过总预算时，优先保留最近结果的较多内容。
- 旧结果可进一步裁剪为短提示，但必须保留工具名、调用标识和原始落盘位置。
- 预算算法不能修改非工具消息。

### F4. 稳定替换账本

- `ContentReplacementState` 按 `toolUseId` 记录替换类型和最终文本。
- 相同历史在不同轮次重复预算处理时输出稳定，避免 Prompt Cache 抖动。
- 会话结束后账本可以释放，本章不要求跨进程恢复账本。

### F5. 自动压缩

- 估算输入达到软阈值时触发自动压缩。
- 低于阈值时不得调用摘要模型。
- 自动压缩后重新估算；仍超限时进入受控恢复，而不是无限压缩循环。
- 连续压缩必须有冷却或进度检查，摘要未有效缩小时停止重试。

### F6. 手动压缩

- `/compact` 可在空闲状态触发压缩。
- 流式请求进行中不得与手动压缩并发修改同一会话。
- 完成后在 TUI 显示压缩前后消息数量、摘要字符数和保留原文数量。

### F7. 上下文过长恢复

- Provider 抛出统一 `ContextTooLongError` 时，Agent 最多执行一次紧急压缩并重试当前模型请求。
- 若压缩失败、没有可压缩内容或重试仍超限，应返回可理解错误并停止本轮。
- 已执行的工具结果和已收到的文本不得重复提交为新的历史消息。

### F8. 恢复附件

- 压缩摘要可附加最近读取文件、当前活动 Skill 和已发现工具的有限摘要。
- 每一部分按明确预算裁剪，不能让恢复附件再次撑满上下文。
- 不存在对应信息时省略该部分。

### F9. 压缩边界

- 成功压缩后通过最小 session 接口追加 `compact_boundary` 记录。
- 边界包含摘要、保留消息定位和创建时间，不包含 API Key。
- 第 08 章可以基于该边界实现完整会话恢复，但本章只保证写入格式稳定。

### F10. 用量与可观察性

- 记录压缩请求与正常 Agent 请求的用量，不把两者混为一次模型响应。
- 自动压缩、紧急压缩、预算替换和熔断应产生可测试的结构化状态或事件。
- 默认 TUI 不展示冗长调试日志。

## 6. 非功能需求

| 编号 | 要求 |
|---|---|
| N1 | 预算处理只操作请求副本，不破坏完整会话历史 |
| N2 | 同一输入和状态产生稳定替换结果，支持 Prompt Cache |
| N3 | 文件写入限制在工作区 `.qicode/` 下并校验标识符，防止路径穿越 |
| N4 | 单个落盘文件、预览长度、摘要输入和恢复附件均有明确上限 |
| N5 | 自动与紧急压缩有次数限制，不形成无限模型调用 |
| N6 | 上下文管理只依赖统一 Provider 接口，不包含 Anthropic/OpenAI 分支 |
| N7 | Node.js 22、pnpm、Vitest 与 TypeScript 严格模式下可验证 |

## 7. 数据流

```text
Agent 准备下一轮请求
  -> 复制完整会话为 apiHistory
  -> applyToolResultBudget(apiHistory)
       -> 大结果安全落盘
       -> 用稳定预览替换
       -> 裁剪旧结果以满足总预算
  -> estimateContext(apiHistory)
  -> 超过软阈值？
       yes -> compact old history -> 重新估算
       no  -> 继续
  -> Provider.stream(apiHistory)
  -> ContextTooLongError？
       yes -> 紧急压缩一次 -> 重试一次
       no  -> 正常进入 Agent Loop
```

## 8. 验收标准

- [ ] 60KB 工具结果被安全落盘，API 历史只包含有限预览，完整历史仍保留原文。
- [ ] 小工具结果不落盘；多次预算处理同一结果得到完全相同的替换文本。
- [ ] 多条工具结果超过总预算时，旧结果被优先裁剪且最近结果保留更多信息。
- [ ] 非法 `toolUseId` 无法逃逸 `.qicode/tool_results/`。
- [ ] 低于阈值不压缩，超过阈值只触发受控次数的自动压缩。
- [ ] `/compact` 能生成摘要、保留最近消息并写入 `compact_boundary`。
- [ ] 模拟 `ContextTooLongError` 时执行一次紧急压缩并成功恢复；再次失败则停止。
- [ ] 摘要请求不携带工具 schema，恢复附件遵守预算。
- [ ] `pnpm typecheck`、`pnpm test`、`pnpm build` 通过。
- [ ] 本章学习文档能解释预算、spill、compact 和恢复链路，并给出对应调试断点。
