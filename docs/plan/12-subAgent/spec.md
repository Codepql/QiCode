# QiCode 第12阶段规格：SubAgent 机制

> 状态：规划中，等待用户明确说“开发第 12 章”后执行。
>
> 前置章节：01-11。本章只定义一次性 SubAgent 与后台任务，不实现 Team、文件信箱或长驻队友。

## 1. 背景

单 Agent 会把探索、实现、验证等工作都放进同一上下文，复杂任务容易污染主会话，也无法把独立
子问题交给不同角色处理。本章引入可定义角色的 SubAgent：主 Agent 可以把一个边界明确的任务
委派给独立会话，并同步等待结果或在后台执行后获取结果。

## 2. 阶段目标

- 支持内置与用户自定义 Agent 角色。
- 子 Agent 拥有独立会话、Provider、权限状态、用量和循环上限。
- 共享经过过滤的工具实现、工作目录和配置，不共享可变会话状态。
- 支持同步执行与后台任务查询/取消。
- 防止无限嵌套和资源失控。

## 3. 本阶段范围

### 包含

- `AgentDefinition`、加载器和覆盖规则。
- 单一 `Agent` 工具，根据 `subagent_type` 选择角色。
- 同步 SubAgent 与后台 `TaskManager`。
- 工具白名单/黑名单、权限模式、模型覆盖和最大轮次。
- 主 Agent 接收最终结果与后台完成通知。
- 取消、超时、失败和用量统计。

### 不包含

- Team、队员信箱、队员横向通信或长驻循环；留给第 14 章。
- Worktree 底层能力；由第 13 章实现。
- 本章自动消费 `isolation: worktree`；只保留字段并在第 13 章接入。
- SubAgent 再派生 SubAgent。
- 跨进程恢复后台任务。

## 4. 功能需求

### F1. Agent 定义

- 内置 `general-purpose`、`plan`、`explore` 三个角色。
- 用户级 `~/.qicode/agents/*.md` 与项目级 `.qicode/agents/*.md` 可覆盖同名内置定义。
- 定义包含名称、描述、允许/禁止工具、系统提示覆盖、模型、权限模式、最大轮次、是否后台、
  可选 isolation、初始提示与 Skill/MCP 选择。
- 名称使用安全 slug；非法文件产生诊断但不阻断其他定义加载。

### F2. 工具过滤

- 子 Agent 永远不能调用 `Agent` 工具，阻断递归派生。
- 系统安全工具和显式拒绝工具优先于角色 allowlist。
- 后台任务使用更小的默认工具集合；写入和命令能力必须经权限系统。
- 工具过滤结果在运行前可观察、可测试。

### F3. 独立运行时

- 每个 SubAgent 创建独立 Conversation、Provider 请求上下文、PermissionChecker、token 统计、
  AbortController 和最大轮次计数。
- 父 Agent 的 API Key 只通过 ProviderConfig 构造，不进入子任务提示词或日志。
- 父子共享的 Tool 实例不得持有会话级可变状态；有状态工具需要为子 Agent 创建实例。

### F4. 同步执行

- 主 Agent 调用 `Agent({description, prompt, subagent_type?, model?})`。
- 同步模式等待子 Agent 完成，工具结果返回最终正文和安全摘要，不回灌完整内部思考。
- 子 Agent 的进度事件可显示在 TUI，但不能与主 Agent 消息历史混合。

### F5. 后台任务

- `TaskManager` 创建唯一 taskId，记录 running/completed/failed/cancelled 状态、结果摘要和用量。
- 后台任务完成后向主 Agent 注入一次通知；通知必须去重。
- 提供查询与取消能力；取消通过 AbortController 传播。
- 进程退出时取消所有仍运行任务并等待有限清理时间。

### F6. 资源限制

- SubAgent 深度固定为 1。
- 并发后台任务数、单任务最大轮次、运行时长和输出长度都有上限。
- 达到上限返回结构化结果，不无限等待或无限调用模型。

### F7. 模型覆盖

- 角色或工具参数可覆盖 model，但仍使用父 Provider 的 protocol/base_url/api_key/thinking 规则。
- 模型别名解析失败时任务失败并返回可理解诊断。
- 不允许 SubAgent 任意覆盖 base_url 或 api_key。

## 5. 非功能需求

| 编号 | 要求 |
|---|---|
| N1 | 子 Agent 与主 Agent 的可变会话状态隔离 |
| N2 | 无无限递归、无限后台任务或无限轮次 |
| N3 | 工具过滤、权限和取消在同步/后台路径一致 |
| N4 | 定义加载错误可诊断，不泄露文件敏感内容 |
| N5 | TUI 不因后台任务阻塞，退出无残留请求 |
| N6 | 只依赖统一 Provider，不含厂商分支 |

## 6. 验收标准

- [ ] 三个内置角色可加载，项目级定义可覆盖用户级和内置定义。
- [ ] 非法定义被跳过并显示诊断，合法定义仍可使用。
- [ ] 子 Agent 无法看到或调用 `Agent` 工具。
- [ ] 同步 explore 任务在独立会话中运行并返回最终结果。
- [ ] 后台任务可查询、取消，完成通知只出现一次。
- [ ] 并发、轮次、时长和输出上限均有测试。
- [ ] 模型覆盖只修改 model，不允许替换凭据与地址。
- [ ] 主会话、子会话、权限和 token 状态互不污染。
- [ ] `pnpm typecheck`、`pnpm test`、`pnpm build` 通过。

## 7. 学习与面试交付

学习文档必须解释 SubAgent 与线程/进程的区别、状态隔离、工具过滤、后台任务状态机、取消传播、
资源上限和为什么禁止递归派生；包含准确调用链、断点、故障实验和一个独立扩展角色练习。
