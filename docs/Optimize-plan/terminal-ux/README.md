# QiCode 终端体验提升：分期规划总纲

日期：2026-11-06

原始诊断基线：`2021d9d`（v0.1.6）。2026-11-07 新增第四期规划；各期实现与验证状态以独立记录为准。

状态：原需求草案保留作历史基线；第一期已落地，第二期“真实编码任务交付”完成本地实现与验证，详见 [第二期实现记录](phase-2-implementation.md)。第三期已进入实现，见 [第三期实现记录](phase-3-implementation.md)。真实模型发布门槛尚未验收。

第四期：[真实任务可靠性与性能](phase-4-reliability/README.md)。本地实现与离线验证见 [实现记录](phase-4-reliability/implementation.md)；真实模型对照与人工终端验收尚未完成。第 2 节保留为原始诊断，不代表现状仍全部缺失。

## 1. 目标与优先级

把 QiCode 从“能在终端运行 Agent”提升为“适合持续编码的终端工作环境”。

用户已明确：**输入、粘贴、滚动和界面稳定性优先**。据此安排：

| 期次 | 用户目标 | 核心交付 | 完成门槛 |
| --- | --- | --- | --- |
| 第一期 | 写得顺、贴得准、翻得动、画面稳 | 编辑器、粘贴、焦点、真实视口、尺寸适配 | 基础操作不丢字、不误发、不串键、不跳屏 |
| 第二期（已重订） | 真正完成编码任务 | 工具协议、任务执行与验证、Shell、长任务、完整恢复 | 有真实改动、有验证证据、失败能修复或明确说明阻塞 |
| 第三期 | 长任务可延续，常用操作少记命令 | 会话选择器、模型选择、上下文状态、任务面板、偏好设置 | 重启后能找到任务并继续，长时间使用仍可管理 |
| 第四期（本地实现） | 真实任务少空转、少打断、交付可信 | 请求计时、上下文闭环、授权验收、源码证据、固定任务对照 | 同条件证据可复盘，关键事实正确，修改通过独立验收 |

三期是产品体验增量，不对应已有 01–14 章节编号；不得因此重新实现已经存在的业务模块。2026-11-06 根据用户反馈重订第二期，以“能干活”为优先级。运行时与工具修复可独立推进，不要求等一期所有视觉工作完成；涉及输入和弹窗的功能继续复用一期机制。

## 2. 基于代码的现状诊断

以下是静态代码审阅结论，尚未通过真实终端复现；需区分“代码中明确缺失”与“终端环境相关风险”。

| 现状与证据 | 对用户的影响 | 安排 |
| --- | --- | --- |
| `src/tui/input-box.tsx` 已有字符插入、左右移动和删除，但 Enter 直接提交，没有明确换行操作、输入历史或逐词编辑；位置按 JS 字符串索引移动 | 长需求编辑费力，emoji/组合字符存在拆分风险 | 一期 |
| 输入组件没有独立的粘贴事务、CRLF 归一化、粘贴折叠状态 | 大段粘贴缺少可检查的交互，跨终端行为需验证 | 一期 |
| `InputBox`、`ChatView`、`PermissionDialog`、`TeamsDialog` 各自使用 `useInput`；没有统一消费与焦点仲裁 | 同一方向键可能同时改变候选、背景滚动和弹窗选项；Teams 打开时输入框仍可能可用 | 一期 |
| 命令候选按完整列表循环选中，渲染只取前 8 项，没有随选中项移动的列表窗口 | 选中项可能不可见，用户不知道 Enter 将选哪个 | 一期 |
| `src/tui/chat-view.tsx` 按估算行高选择整轮对话，再渲染完整回合，没有按行裁剪视口 | 单个超长回合仍可能超高；翻页位置不精确 | 一期 |
| `src/tui/app.tsx` 用固定行数估算界面占用；多行通知、候选、团队树和权限弹窗高度不统一计算 | 小窗口或内容展开后输入区可能被挤走 | 一期 |
| 流式回复用纯文本显示，结束后切 Markdown 渲染 | 完成瞬间可能重新换行、产生阅读位置跳变 | 一期 |
| `InputBox disabled={busy || permissionRequest !== null}` | 运行期间无法继续起草或提交调整意见 | 二期；一期先保留运行前草稿 |
| `src/tui/tool-display.tsx` 将参数截到 80 字符、结果截到 500 字符，没有详情入口 | 用户看到省略号后无法在界面继续查看 | 二期 |
| `AgentEvent` 已包含工具耗时，但完成工具的聊天展示未传入耗时 | 已有数据未转化为执行反馈 | 二期 |
| `/resume`、`/rewind`、`/compact`、命令注册、Skills、MCP、SubAgent、Team、Worktree 已有实现 | 后续重点是入口和可管理性，不应当作全部从零新增 | 二、三期 |
| 状态栏显示累计输入/输出 token；`contextWindowFor` 按协议返回固定容量 | 累计用量不能当作当前上下文占用，固定容量不能代表所有模型 | 三期 |

README 的路线图落后于源码；本规划以源码为现状依据。最近已有 resize 重复输出修复，应补覆盖并验证残余问题，而非默认该修复无效。

## 4. 第一期：输入与阅读基础体验

功能代码与自动化测试已实现，见[第一期实现与验收记录](phase-1-implementation.md)。真实终端人工验收仍待执行，以下需求保留作为验收基准。

### P1-01 多行编辑器（必做）

用户可以在终端里编辑完整需求，不依赖一次性输入。

- Enter 发送；Shift+Enter 换行；Ctrl+J 提供可配置的换行备用键。两种按键都必须在目标终端验证，不支持时显示可用替代方式。
- 支持上下左右移动、Home/End、Ctrl+A/E 行首行尾、Ctrl+Left/Right 逐词移动、Ctrl+W 删前词、Ctrl+U/K 删到行首/尾。
- 退格与光标移动以用户感知字符为单位，中文、emoji、组合重音字符不出现半个字符。
- 编辑器自动增高，最多占可用高度的约三分之一、且不超过 8 行；超出后在编辑区内滚动。极小窗口优先保留当前光标行。
- 空白内容不发送；文本原始缩进和首尾换行不因统一 `trim()` 而丢失。
- 一期新增当前项目输入历史：方向键只在编辑器首/末行边界浏览已提交历史；离开历史返回当时草稿，不覆盖尚未发送内容。
- 运行前已有草稿遇弹窗、缩放和输入禁用时保留；一期不承诺运行期间继续编辑，由二期提供。

验收：输入包含中文、emoji、缩进代码的 20 行需求，移动并修改中间行，换行不提交，Enter 只发送一次；光标和删除无字符损坏，重排后草稿内容一致。

### P1-02 可靠的文本粘贴（必做）

- 支持 bracketed paste；粘贴中的换行全部作为正文，不触发提交或 Slash 命令执行。
- CRLF/CR 统一为 LF，保留缩进与空行；过滤终端控制序列，不将粘贴文本当按键执行。
- 超过 10 行或 2,000 字符时，显示“已粘贴 N 行 / M 字符”的折叠块，可展开、编辑、移除；提交给模型的是完整文本，不是占位说明。
- 支持连续粘贴多个片段，插入位置正确；删除一个折叠块不影响其他片段。
- 初始输入上限为 1 MiB UTF-8 文本。超限时拒绝本次粘贴并说明原因，保留原草稿，不静默截断；该限制不代表模型可用上下文容量。
- 不能可靠识别粘贴边界的终端提供明确的“粘贴模式”入口：其中 Enter 只换行，通过独立确认操作提交；普通按键流无法区分输入与粘贴时不宣称自动识别可靠。
- 本期仅做文本粘贴；图片和附件另行评估。

验收：分别粘贴 1 行、30 行、1,000 行文本，以及带中文、反引号、Slash、ANSI 控制字符的内容；不误发、不执行命令、不丢缩进；CRLF 转换后的发送内容与预期一致；超限不损坏原草稿。

### P1-03 统一焦点与按键消费（必做）

按键优先级：当前模态弹窗 > 补全列表 > 编辑器 > 聊天快捷键；只有未消费事件进入下一层。

- 一次按键只能由一个作用域消费；打开模态弹窗后，背景输入、历史和聊天滚动冻结。
- ↑/↓ 在命令列表中仅移动选项，在编辑器内仅移动光标或浏览历史；聊天翻页使用 PageUp/PageDown，Ctrl+Home/End 到顶部/最新。
- Home/End 优先属于编辑器，不再同时触发聊天跳转。
- Esc 先关闭候选或弹窗；没有此类界面时才取消当前执行。权限弹窗 Esc 仅拒绝本次请求，不退出应用。
- Ctrl+C 执行中取消；空闲时保留现有“两秒内再按一次退出”。焦点弹窗先处理取消，帮助文案与实际行为一致。
- 候选列表超过一屏时随选中项滚动，始终显示选中项；Tab 补全，精确命令 Enter 执行，其余 Enter 先填入命令，保持现有规则并给出提示。
- Ctrl+T 打开团队面板，Shift+Tab 权限切换保留，不照搬 pi 的同名按键含义。

验收：准备 30 个命令候选，遍历首尾都能看见选中项；权限或团队面板中按方向键、Enter、Esc，背景聊天位置和草稿不变；关闭候选不取消任务。

### P1-04 真实聊天视口与阅读锚点（必做）

- 聊天区受实际可用行数约束，单条回复超过一屏也能逐页查看，不通过渲染整个回合突破窗口高度。
- 用同一套字符宽度、换行和 Markdown 布局结果驱动渲染与滚动，不让“估计高度”成为唯一定位依据。
- 在底部时跟随新输出；用户上翻后停止跟随，并显示“有新输出 / 回到最新”。Ctrl+End 恢复跟随。
- 用户阅读历史时，以消息 ID 与内容位置保持锚点；流式追加、工具结果更新、窗口缩放不强制跳到底部。
- 流式与完成态使用一致的 Markdown 布局规则；未闭合代码块可增量展示，完成后不重复插入已有内容。
- 同时解决较长代码行、中文宽字符、列表和表格的边界；代码保留完整内容，表格允许窄屏降级显示，不溢出覆盖输入区。
- 支持目标终端中的鼠标滚轮回看与文本复制。若选择捕获鼠标，必须保留并提示终端选择复制的操作；不支持鼠标捕获的终端仍可键盘完成阅读。

验收：单条 500 行回复、50 轮历史、100 列代码行及中英混排；每段内容可到达，无重复或遗漏；上翻期间持续接收 10 秒输出，阅读锚点保持；回到最新只需一次操作。

### P1-05 布局、缩放与中文输入稳定性（必做）

- 顶部、聊天、编辑、状态和弹窗统一分配高度；通知和候选展开时按实际行数重新布局。
- 保留原来的三行 ASCII 猫咪 Logo 与 Header，不替换为单行猫脸、不自动改变样式；窄窗口沿用原 Header 的尺寸规则。无团队时不占常驻团队树区域。
- 80×24 正常显示，60×16 紧凑显示；40×10 使用降级布局，保留编辑光标行、必要状态和退出/确认入口。再小则显示尺寸提示并保存草稿。
- 正常尺寸下输入区和状态区始终可见；弹窗内容过高时自身滚动，确认入口不得位于无法到达的位置。
- resize 合并处理，重排不重复消息、不重置草稿和焦点；空闲不做无意义的整屏刷新。
- 中文输入法候选位置跟随当前编辑光标；不把硬件光标停在无关区域。若组件抽象无法保证，纳入技术路线复核。
- 界面状态和错误提示默认中文，保留工具、模型和命令原名；不要求翻译模型回复。状态同时使用文字或符号，不只依赖颜色。

验收：连续 20 次在 120×40、80×24、60×16、40×10 之间切换，分别覆盖输入中、输出中、候选打开、权限弹窗打开；无重复消息、草稿丢失和不可达操作。真实中文输入法下验证候选窗口和提交行为。

## 5. 第二期：真实编码任务交付（新版）

**本节替代原先以工具展示、队列和复制导出为主的第二期。** 用户最新反馈是“简单问答可以，真正干活差距很大”，因此将运行时、工具与验证闭环升为首要交付。

新版完整规划：

1. [需求与验收目标](phase-2-delivery/spec.md)：代码差距、pi 对照、需求优先级、完成定义。
2. [技术方案](phase-2-delivery/plan.md)：执行状态、协议、工具、持久化和控制边界。
3. [实现任务](phase-2-delivery/task.md)：按单人开发顺序拆解，先得到最小可用闭环。
4. [验收清单](phase-2-delivery/check.md)：真实任务、故障注入、模型对照与发布门槛。

保留工具状态、权限详情、取消与错误反馈，但它们必须服务于完成任务。通用后续任务队列、复制导出、复杂工具浏览器、外观偏好转入后续体验积压项，不阻塞新版第二期。运行中“补充当前任务”只做最小闭环，复用一期焦点与输入能力。

| P3-06 | 复用团队状态和 Worktree 后端，提供按需打开的任务面板：执行中/完成/失败/取消、最近动作、所属分支/目录、详情入口 | 多成员更新不挤走主输入区；详情可滚动；取消单个任务不误取消全部；无后台任务时保持简洁 |
| P3-07 | `/rewind` 升级为检查点预览与选择：展示时间、受影响文件、冲突和恢复范围 | 必须区分恢复文件与恢复对话；外部修改冲突明确展示；取消预览不写文件；不能承诺撤销外部命令副作用 |

上下文容量新增为独立的模型能力元数据，不随意增加 Provider 协议种类。保持当前 `anthropic/openai` 两协议；模型能力缺失时明确未知，不沿用协议固定容量冒充精确值。

本期不强行复制 pi 的会话树和任意历史分叉。先做好线性会话恢复与文件检查点；通用分叉需要独立讨论消息分支、文件状态及存储迁移。

## 7. 建议落点与实施顺序

以下是需求到模块的映射，不是本轮代码改动或已承诺的接口设计。

| 关注点 | 当前模块 | 建议变化边界 |
| --- | --- | --- |
| 编辑、粘贴、历史 | `src/tui/input-box.tsx` | 拆分可独立验证的编辑状态、粘贴状态和显示组件 |
| 焦点、键盘、弹窗 | `src/tui/app.tsx` 及各组件 | 应用统一管理焦点与命名动作，子组件不再无条件处理相同事件 |
| 内容布局和视口 | `src/tui/chat-view.tsx` | 分离内容布局、消息锚点和可见行选择，缓存稳定内容 |
| 尺寸与状态 | `src/tui/header.tsx`、`status-bar.tsx`、`activity.tsx` | 统一布局预算与密度降级；状态使用同一数据来源 |
| 工具和运行过程 | `src/tui/tool-display.tsx`、`src/agent/events.ts` | 复用 tool ID、状态与耗时；仅必要时扩展事件 |
| 补充输入和队列 | `src/tui/app.tsx`、`src/agent/agent.ts` | 独立队列状态，在明确安全边界消费，不塞进 Provider |
| 会话与回退 | `src/session/session.ts`、`src/filehistory/filehistory.ts` | UI 复用现有存储与恢复；新增元数据需兼容旧文件 |
| 命令入口 | `src/commands/commands.ts`、现有模块命令 | 全部通过现有 CommandRegistry 扩展，不增加第二套分发 |

一期实施顺序：焦点与按键消费 → 编辑与粘贴 → 内容布局与视口 → 尺寸/IME → 真实终端回归。每步都以长回复、中文草稿和模态弹窗做组合验证。

二期顺序以新版任务清单为准：基准定位 → 协议可靠性 → 命令与编辑可靠性 → 修改验证闭环 → 长任务与恢复。三期继续做会话与模型的使用入口、偏好和任务面板；其中支撑二期交付的上下文预算与完整持久化提前到二期。

## 8. 验收方法与交付门槛

### 8.1 支持矩阵

优先实测 Windows Terminal + PowerShell 7、VS Code 集成终端 + PowerShell；补测 macOS Terminal、Linux 常见终端 + bash/zsh。执行时记录操作系统、终端版本、Shell、输入法和尺寸。

Windows 两项为一期发布硬门槛；未实测的平台明确标为待验证，不能用组件测试结果声称已兼容。远程 tmux、终端图片、所有键盘协议兼容不列为一期硬门槛。

### 8.2 基准场景

1. 编辑 20 行中文/emoji/代码混排需求，粘贴 1,000 行错误日志，修改后发送一次。
2. 模拟 Provider 连续输出 500 行 Markdown；阅读中上翻、翻页、回到最新。
3. 30 个命令候选和 50 轮历史同时存在，选择候选时背景不动。
4. 权限弹窗、团队面板依次打开关闭，草稿、焦点与阅读锚点正确恢复。
5. 输入/输出/弹窗期间连续 resize；退出后终端回显、光标、颜色和输入模式恢复。
6. 二期追加工具失败、超时、补充意见、排队、撤回和取消；三期追加重启恢复、模型切换、压缩与检查点冲突。

### 8.3 量化目标（拟定验收阈值，非现有性能结论）

使用假 Provider、假工具和固定数据集，记录测试机器、Node 版本、终端及至少三轮结果；不把真实模型延迟计入 UI 响应。

| 指标 | 目标 |
| --- | --- |
| 普通输入到本地画面更新 | p95 ≤ 50ms |
| 1,000 行、约 100 KiB 文本粘贴到折叠摘要可见 | p95 ≤ 200ms |
| 翻页、候选选择、弹窗开关 | p95 ≤ 100ms |
| resize 停止到布局稳定 | p95 ≤ 200ms，无消息重复 |
| 连续 30 分钟脚本化使用 | 零草稿丢失、误发、串键和不可恢复的焦点丢失 |
| 输入数据一致性 | 除约定的换行归一化、控制字符过滤外，发送文本完全匹配预期 |

性能测试单列 50 轮、每轮 200 行的历史和 20 次/秒流式事件；通过缓存与更新合并保障输入响应。记录内存变化并调查持续增长，不以未知硬件上的绝对内存值作为虚假承诺。

### 8.4 开发完成时的验证

- 纯状态测试：字素编辑、粘贴、焦点优先级、滚动锚点、队列顺序与取消。
- Ink 组件测试：候选可见、模态隔离、动态高度与降级文案，复用 `tests/tui`。
- 本地集成测试：假 Provider 和工具覆盖流式完成、失败、取消、权限与恢复，不使用真实 API Key。
- 真实终端验收：输入法、粘贴协议、鼠标/选择复制、resize 和退出恢复。组件快照不能替代这些验证。
- 每期完成运行 `pnpm typecheck`、`pnpm test`、`pnpm build`，提交场景证据、已知兼容性限制和回归结果。

## 9. 本轮范围与后续决策

本轮在三期总纲上重新交付第二期的需求、方案、任务与验收定义。第一期默认采用基于 Ink 的渐进修整；本次仅编辑规划文档，不实施 Agent/工具变更、不替换 Provider、不升级依赖、不发布 npm。

按用户最新优先级，下一开发重点是第二期 T01 基准定位，以及协议、Shell、修改验证闭环。第一期的焦点、编辑粘贴和视口作为交互基础继续保留；后端修复可以独立推进。第三期仍保持产品需求粒度，避免提前锁死未知实现。
