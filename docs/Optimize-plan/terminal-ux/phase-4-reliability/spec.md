## 3. 指标定义

- **总耗时**：接受用户提交到最终结果落定，包含授权等待；同时报告扣除授权等待的有效耗时。启动和用户输入时间单列，不随意混入。
- **请求首事件 / 首文本**：从一次请求开始，到第一个合法流事件 / 第一个非空文本增量。先返回工具或隐藏思考时，首文本可以为空，不把它算作卡住或伪造为零。
- **首次工具**：工具真正开始执行，不是模型刚提出调用。不等于模型首字时间。
- **压缩**：区分尝试、成功、失败、无收益、跳过；计时与用量独立于主请求。自动和手动压缩分开。
- **读取重复**：相同版本、相同或重叠范围的再读取；冲突复核、补充分页和磁盘变化后的重新读取单列，不一律算浪费。
- **人工干预**：区分授权选择、任务补充、纠正方向、手工编辑与预设重启。首次按 T 与后续反复确认分开统计。
- **任务成功**：独立验收器通过、没有越界改动、无需用户额外提示“继续干活”。检查通过、模型自述和 `completed` 标记不能单独证明成功。
- **成本**：输入、缓存输入、输出按 Provider 实际字段和口径记录；没有可信计价来源时只报用量和费用未知。

## 4. 固定任务的拟定目标

以下为目标，不是现有结果或通用 SLA：

| 场景 | 目标 | 限制 |
| --- | --- | --- |
| 当前源码追踪任务 | 自动成功压缩不超过 2 次；不存在连续无效压缩；八项证据检查无关键事实错误 | 固定提交、新会话、已明确模型容量；不适用于任意长度任务 |
| 普通编码流程 | 按 T 后同一任务符合范围的后续步骤不再询问 | 高风险、规则要求、越界、未知效果单独计数，不为达标关闭保护 |
| 查看/审查 | 不擅自写文件或跑全量检查，回答与请求匹配 | 用户明确要求验证时按范围执行 |
| 修改与验证 | 不因一组失败检查提前耗尽修复轮次；最终验证对应最新修改 | 不弱化验收器，不自动安装依赖 |
| 恢复与草稿 | 同一现场多次恢复不增加重复上下文、不重复副作用、不带回已发送草稿 | 冲突或未知状态明确要求核对 |

性能改善优先看同条件多次运行的中位耗时和完成质量，不要求在不同模型、网络和任务上“一律比 pi 快”。小样本不报告不可靠的 p95。

## 5. 用户控制与约束

保持现有快捷键、Logo、权限模式和线性会话。任务授权可通过取消当前任务结束，不默认永久全放行。性能记录仅本地，默认不新增原始 prompt、响应正文、命令正文或环境变量副本；已有会话日志与性能记录分别说明保存范围。导出须脱敏并由用户选择，不自动上传。

不记录隐藏思考内容。源码证据记录保存路径、版本、行范围、工具标识和可核对结论，不保存模型思考过程。
