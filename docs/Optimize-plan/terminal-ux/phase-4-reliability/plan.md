# 第四期技术方案

日期：2026-11-07。本文保留方案及设计边界；实际接口、已验证内容和待验收项见 [实现记录](implementation.md)。

## 1. 最小本地时间线

复用 `runSession` 与现有 JSONL 生命周期，新增独立性能记录或兼容的版本化记录，不另造会话存储系统。旧会话忽略未知事件仍可恢复；性能写入故障必须可见，但不能在工具已生效后把整个任务重放。

每次运行建立 `runId`，每个主模型请求建立 `requestId`，重试尝试建立 `attemptId`；工具继续使用原 `toolId`，压缩请求标 `purpose=compaction`。主任务、子任务和团队成员记录父子关系，不混成一个用量计数。

建议事件：运行开始/结束、请求开始/首事件/首文本/结束、工具开始/结束、授权开始/结束、压缩开始/结束、退避开始/结束。用单调时钟计算持续时间，UTC 时间只用于跨记录关联。取消、超时、错误均通过 finally 收尾；强制退出缺少结束事件时显示未知，不能填 0。

记录模型、协议、能力来源和预算，端点用不含凭据的本地标识区分，不复制完整 URL。用量按协议正确合并，处理 Anthropic 输入开始事件与输出结束事件、缓存字段及重复累计 usage，不能把 output-only 事件当成输入归零。

提供一条通过现有 CommandRegistry 注册的本地性能详情入口，例如 `/stats`，先给总耗时、有效耗时、请求数、压缩次数和主要等待原因，详情才显示时间线。最终命令名实施时检查冲突；不先做常驻多行仪表盘。

## 2. 上下文预算闭环

建立统一的有效预算解析入口，供主 Agent、fork、团队、压缩和状态栏使用。来源顺序为用户明确能力覆盖、项目已知元数据、保守默认；缺失时显示未知和采用的预算，不根据协议猜容量。

发送前统一核算：系统提示、工具 schema、提醒、预算后的消息和输出预留。服务端输入量用于校准估算，保持输入/输出/缓存口径；已有累计会话用量不参与占比计算。

工具结果继续完整落盘、上下文使用有界预览，不删原始证据。压缩按消息预算选择近期消息，保留工具配对、任务目标、授权边界、当前改动、验证记录、定位信息和未完成事项。恢复附件只放已观察到的片段与指向，不补读全文。

记录压缩前后估算、保留数量、摘要量和收益；目标是在固定任务中为下一轮留出余量。窗口过小、摘要无收益、文件被外部修改时分别处理，不用提高压缩次数上限掩盖问题，也不为满足次数目标丢弃必要约束。复用现有熔断和上下文超长恢复出口。

## 3. 授权作用域保持一致

复用 T 任务授权与 `taskApprovalEligible`，不新增第五种默认权限模式。审批界面显示批准范围和有效期；本次允许、任务允许、永久精确规则有明确区别。

每次实际调用仍先经过危险命令、沙箱和显式规则检查。未知效果不使用任务批量批准。新任务、恢复后继续、模型切换及子 Agent 的授权行为要有一致说明和离线覆盖；不默默把父任务授权扩大到所有子 Agent。

记录授权事件的工具类别、策略来源、结果与耗时，不在性能日志复制命令正文。Shell 筛选是启发式，不能宣传为完整安全沙箱。

## 4. 读取与事实证据

复用 ReadFile 的文件版本信息和结构化结果，补充可恢复的已读范围标识。第一步先定位函数/符号，再读必要片段；多文件独立读取可同轮提出，后续读取基于已有证据继续。

同一文件重复读取时区分：新的分页、冲突复核、版本变化、相同范围重读。第一版先记录并提示，测出浪费后再考虑缓存；不直接跳过读取，不以 mtime 相同就保证内容未变，更不能破坏读后写校验。

源码追踪输出先主链，再关键数据转换，最后列正常与异常退出。关键事实绑定实际函数/调用点；没有读取的实现明确未覆盖。审查输出缺陷，修改输出交付，用户要求详细解释时允许展开，不能统一缩成提升清单。

完成前核对“每条路径”“一定”“直接丢弃”等全称结论的实际分支，优先防止已有实测中的事实错误。先用任务记录与人工验收清单评估，不默认增加另一次收费模型审阅。

## 5. 真实任务与同条件对照

复用 `benchmarks/` 的固定副本、工作区外验收器与恢复检查，新增真实模型运行记录适配；离线脚本 Provider 与真实模型报告严格分开。

最小诊断集为五项：源码追踪、明确 bug、小功能/多文件联动、真实失败后修复、退出恢复继续。先各跑一次定位失败分布，再冻结目标、起点、模型、预算和授权条件；正式小对照每项 3 次，QiCode 15 次、pi 15 次。未获得对应网络/费用授权不启动，用户已自行产生的合法记录可导入分析。

这套小对照只用于快速诊断与改进，不能代替二期既定 10 场景 × 3 次发布验收。重叠场景符合相同条件时可复用证据，避免重复消耗。pi 不支持相同协议/模型时标记不可直接比较，不偷偷换模型。

## 6. 代码落点

| 需求 | 优先复用模块 | 边界 |
| --- | --- | --- |
| 计时与记录 | `agent.ts`、`events.ts`、`run-session.ts`、两个 Provider | 独立记录职责，不继续把全部统计堆进 `app.tsx` |
| 容量与压缩 | `execution.ts`、`load-config.ts`、`compact.ts`、`recovery.ts`、`toolresult/` | 一份预算结果服务所有入口 |
| 授权 | `checker.ts`、`task-approval.ts`、`permission-dialog.tsx` | 保留检查顺序与明确授权，不放宽拒绝规则 |
| 读取与证据 | `read-file.ts`、Conversation、RecoveryState | 扩展结构化元数据，保持原始内容和版本保护 |
| 展示 | 现有任务详情、通知和状态栏 | 摘要常驻、细节按需，不挤压输入区 |
| 对照 | `benchmarks/`、本地分析记录 | 独立验收、离线默认、模型调用显式启动 |

文件格式新增字段保持可选、带版本。先完成一条从输入到结果的纵向路径，再扩展其它入口；避免一次大重构。
