## 2026-11-08 容量与压缩补充

容量优先级为调用方明确覆盖、`model_capabilities` 显式配置、已核实且匹配端点的内置模型资料、未知模型的保守预算。当前内置官方 DeepSeek 端点下 V4 Flash/V4 Pro/Flash 的 1,048,576 容量，输出请求预算保持 8192；资料依据 [官方 V4 发布说明](https://api-docs.deepseek.com/news/news260424/) 与 [模型元数据说明](https://api-docs.deepseek.com/api/list-models/)，代理端点不自动继承。未增加启动时模型 API 调用，也不读取其它 Agent 的凭据或配置。

统一预留包含输出预算和有上限的余量，不再叠加扣输出与 15% 容量。1M/8K 时自动压缩阈值为 1,032,192；未知 32K/8K 为 24,576。输出预算较大时会降低阈值，以实际配置为准。

主任务、子任务、fork、团队成员、手动压缩与模型详情采用同一解析结果。自动压缩与发送前预检共享服务端输入 usage 校准，加后续新增消息并调整系统/schema/临时提醒开销；同一次请求分段返回的输入与缓存用量合并，不被 output-only 或零用量覆盖。Conversation 的历史替换代次使压缩、恢复、清空、回退后的旧校准失效，包括消息数恰好相同的情况。

本批相关离线检查共 82 项最终通过，类型检查通过；未运行全量、构建或真实模型对照。此前报告的真实失败仍保留，不能据此声称所有长任务已不再压缩。

## 体验方式

运行 `pnpm dev`，完成一次任务后输入 `/stats`。运行中也可以查看，不触发额外模型请求。

| 入口 | 行为 |
| --- | --- |
| `/stats` | 当前或最近一次任务：总耗时、授权等待、有效耗时、首次工具、首文本、请求与重试、压缩和用量 |
| `/stats list` | 最近最多 50 条运行记录及模型、状态、父运行标识 |
| `/stats children` | 最近记录中属于当前主任务的子任务；父子时长和用量分开，不直接相加 |
| `/stats <运行标识>` | 查看指定本地记录，包括最近 12 次文件读取范围、版本及重复/重叠情况 |
| `Alt+T` | 现有任务详情附本轮性能信息；入口仍服从用户快捷键设置 |
| `Ctrl+N` | 展开较长的通知，以 PgUp/PgDn 浏览 `/stats` 详情 |

原来的三行猫咪 Logo 保留。统计不占用新的常驻面板。已知模型容量显示配置来源；未配置的容量使用 32,768 上下文、8,192 输出的保守预算，状态栏标“保守”。该数值不代表模型真实容量，已知能力应在现有 `model_capabilities` 配置中明确填写。

## 实际改动

- `src/metrics/`：版本化本地时间线，关联 run/request/attempt/tool 与 parent；单调时钟计时。区分主请求、摘要请求与后台记忆请求。首事件和首文本独立，工具开始以实际执行回调为准。压缩记录触发来源、前后消息估算、近期保留量及摘要长度。
- 每个请求尝试内合并累计 usage，忽略重复快照；不同尝试再累加。保留 output-only 更新前的输入与缓存字段。用量不完整和价格未知明确显示，不把费用记作零。
- 主任务、fork、子任务、团队与手动压缩复用 `resolveBudget`。子任务切换模型时解析实际模型的能力；不沿用另一个模型的窗口。子任务默认总预算与主任务统一，用户显式配置仍生效。请求空闲、总任务、命令限制各自保留。
- 发送前估算包括系统提示、工具 schema、提醒及预算后的消息，预留输出空间。自动和手动压缩使用相同窗口口径，手动压缩与超长恢复也先预算工具输出。没有收益不替换原对话；既有三次无效压缩熔断、工具配对、磁盘完整输出继续生效。
- 父子任务共享授权等待时钟，等待时暂停相应执行预算；授权本身仍各任务独立。模态审批按队列展示，取消某个排队任务不会把答案给另一个任务。初始化和审批等待可取消，忽略 AbortSignal 的模型流也有可结束的空闲超时记录。
- ReadFile 返回实际观察到的内容哈希、行范围和总行数；结构化会话保存可选证据字段。恢复后可识别重复范围，磁盘内容变化则标记 changed。恢复附件只使用观察片段，不为了统计再次读取全文；历史证据不赋予读后写权限。
- 继续复用任务级 T 授权、精确权限检查、交付 revision 验证、失败修复轮次与未知副作用不自动重放机制，没有另造审批模式或自动跳过重复读取。

统计文件在 `.qicode/metrics/<runId>.jsonl`，已有 `.gitignore` 排除；每条记录只含元数据，端点按 origin/path 做短哈希，不保存完整 URL、认证头、环境变量、隐藏思考、提示词、回复和命令正文。文件路径与模型名称属于可识别的本地元数据，不自动上传。已有会话与工具日志本来会保存正文，其保存范围不因性能记录而改变。

每次最多 10,000 个元数据事件、8 MiB 文件。记录保存失败提示警告，任务继续，不重放请求或工具。强制退出缺结束事件时总耗时和有效耗时显示未知；仍在运行时不把“已观察时长”冒充最终耗时。各阶段可能重叠，授权等待取区间并集，不把请求、工具、压缩简单求和。

后台记忆请求独立记录，父任务无法可靠归属时不猜 parent；主任务统计不含其后台尾时。当前没有自动清理历史性能文件；长期使用可在任务停止后自行整理 `.qicode/metrics`。

## 离线诊断与对照准备

`pnpm benchmark:phase4` 默认不使用 API。冻结 HEAD、当前 src/benchmarks/构建配置的内容指纹与既有 fixture/验收器指纹；复用 B01/B03/B04/B10 的临时工作区和工作区外独立验收器。F01 源码追踪保留八项人工事实核对，不用脚本模型生成一篇答案后自称事实验收通过。

只冻结：`pnpm exec tsx benchmarks/run-phase4.ts --freeze`。

分析用户已有对照：`pnpm exec tsx benchmarks/run-phase4.ts --review <本地JSON文件>`。输入包含非空 `baseline`、`conditions` 和 `records`；单条记录结构见 `ComparisonRecord`。要求同一基线/条件、QiCode 与 pi 各五项三次，保留失败与人工干预；F01 成功记录必须有八项事实核对，关键错误直接不通过。该命令不启动模型、pi 或上传文件。

对照记录依赖人工确认来源与条件；布尔字段不能独立证明事实正确或没有越界。未填写真实模型、端点标识、thinking、能力、预算、授权与缓存条件，或 pi 版本未知时不能声称严格可比。未知价格仍是未知。小对照不代替二期 10 场景 × 3 次发布门槛。
