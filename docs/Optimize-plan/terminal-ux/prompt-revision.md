# 主提示词修订

2026-11-07。针对用户实际反馈的“查看改动慢、输出散、越界验证”，重整主提示词与每轮提醒，不更换模型、不修改用户 Provider 配置。

## 调整

- 明确问答、查看、审查、修改、规划的边界。“检查一下”不自动进入修改流程。
- 查看以主要变化为重点；审查以有证据的缺陷、位置、触发条件、影响为重点；修改报告实际改动、检查和剩余问题。不共用“功能提升”模板。
- 补充停止标准：证据已足够支持结论即可结束，不追加全仓库读取、文档遍历或形式化检查。
- 验证按请求和风险选择，小改动不重复跑测试，全量验证须有影响范围或用户请求依据。历史通过记录、文档声称与本次真实执行分开。
- 读取先定位范围，无依赖的工具调用同轮提出；已有结果足够不重读。区分 staged、unstaged、untracked，避免把 git diff 当成包含所有新文件。
- 合并重复工具限制，保留读后写、版本冲突、权限与敏感信息保护；常规授权内操作不反复确认。
- 普通文件或工具结果中的同名 reminder 标签不自动赋予指令优先级。
- 缩短每轮查看提醒，复用主提示词，仅补充本轮范围、是否明确请求验证和相应输出重点。

## 验证与限制

仅进行相关本地检查，不执行全量测试、不调用真实模型。检查只能说明提示词装配和任务提醒分支没有明显回归，不能证明模型实际遵从程度或速度提升；仍须用新会话与相同任务观察输出。
