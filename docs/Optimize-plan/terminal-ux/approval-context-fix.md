# 任务授权与反复压缩

2026-11-07。用户要求优先解决多次回车和反复压缩，沿用现有权限模式，不静默改为全放行。

## 授权按任务生效

以前 Y/Enter 只批准一个工具调用；A 只记住完整字面操作，文件或命令变了仍会再次询问。

新增 T：当前 Agent 任务内允许已知编辑工具和普通 Bash 命令。无需回车，后续符合范围的操作连续执行。任务结束失效，不保存永久规则；每个新任务重新获得授权，子任务不自动继承父任务授权。

危险命令、路径越界、显式规则、恢复后结果未知操作保持原有检查。识别出的推送、发布、安装、删除、外部连接等命令及其它工具不使用任务批量批准。命令识别是启发式范围筛选，不是完整 Shell 沙箱；脚本内部行为不能仅从命令名字证明。

## 让压缩腾出实际空间

此前已修正恢复附件把整文件重新塞入、输入输出计数重复等问题。本轮继续处理：

- 工具结果 API 预算随窗口缩放。保守 32768 上下文、8192 输出预算时，单结果超过约 17203 字符便保存完整内容到本地，模型收到预览和路径；同条结果消息也有合计预算。原始历史和工具结果仍完整保留。
- 大窗口保留原先 50000/200000 字符的默认上限，不把所有模型统一缩成小窗口。
- 已经落盘的预览不重复覆盖原始溢出文件。
- 压缩后估算若没有下降，不替换原会话，也不算成功。
- 连续三次失败或无效压缩时熔断；如果仍处于硬限制区间，明确停止并保留原对话，提示缩小读取范围或核对容量配置，避免继续几十轮空转。

没有人为抬高未知模型容量。真实容量仍由 `model_capabilities` 按模型名配置；未知时继续使用明确标注的保守预算。
