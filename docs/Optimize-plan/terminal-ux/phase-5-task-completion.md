# 第五期：任务完成与执行收敛

日期：2026-11-24，更新于 2026-11-25。开发基线为 `422e958`。本地执行环境已恢复，5A 和 5B 的首批功能已接入，验收进度见下文。

## 首批实现

- 当前会话的模型问答在 App 内直接读取选中的运行配置，并写入现有会话和性能记录。正常任务的模型请求附带当前模型、协议、权限与预算，供回答时参考。只有记录到项目文件改动的成功任务才可能触发后台记忆提取。
- 执行、验证提醒与交付共用只读和验证约束解析。提交与追加输入分别传递用户原文、引用内容。明确只读的任务允许内置读取工具及窄范围 Git 查看命令，写入、任意命令和外部 Hook 操作受限。识别的是当前支持的明确表述，带有歧义的自由文本仍需后续实测。
- 交付记录增加停止原因、成功工具计数与未知副作用标记，消息先于终态交付落盘。已有有效文本与工具详情可在失败后回看，取消也进入统一终态。重复读取仍可执行，同一只读任务第三次重复读取时会提醒一次。
- 本地回归覆盖零模型请求、只读阻止写入与测试、低风险修改跳过验证追问，以及断流后保留部分结果。第四期复用的 B01/B03/B04/B10 四项脚本诊断均通过。真实进程重启、真实模型对照、实际仓库任务独立验收与终端人工验收仍待完成。

## 目标

简单问题直接回答，复杂任务读得有目的、遇到失败能恢复、证据够了及时交付。优先改善任务完成率与用户等待，不继续以面板数量、提示词长度或工具调用次数衡量能力。

保留原猫咪 Logo、现有 Markdown 回复样式、线性会话、权限模式和配置兼容性。第四期真实模型/终端验收仍保留，不因进入第五期自动视为通过。

## 实施顺序

### 5A：先让简单任务变轻

1. 核对当前实现与冻结基线，重用第四期采集。
2. 在已有提示构建/请求路径中统一非敏感运行时事实，覆盖模型切换后的当前值；不增加一轮收费模型判断任务类别。
3. 优先统一 task-intent 与 TaskDelivery 的请求语义，明确只读/执行及验证要求，供 Agent 工具约束、交付提醒和记忆触发共用。复用现有模块；只有职责确实需要时再拆文件，不引入任务规划框架。
4. 调整 App 的后台记忆触发策略，避免简单问答另发 auxiliary 请求；联动交付逻辑，防止低风险修改完成后仅为说明“未验证”再次请求模型。
5. 交付简单问答、明确只读审查与低风险小改动三个回归场景；记录主请求、摘要、后台请求与工具，不只观察前台回答。

退出条件：简单问题不再主动扫描仓库或请求无关授权；用户不需要说“继续”才得到答案。

### 5B：让调查收敛，失败有结果

6. 先统一 Agent 错误出口与 App 显示的交付信息：包括终态、停止原因、有效文本/工具证据位置、未完成范围和是否存在未知操作；沿用已有 DeliveryReport，新增字段保持可选，旧会话可恢复。
7. 建立有界任务进展信息，优先复用已有读取版本/行范围、交付 revision 与验证状态，不默认增加一次模型总结。任务事实只记录已观察或明确声明的内容，不能本地推断“问题已经解决”。
8. 在可控记录中测重复行为，再决定是否加入一次轻量的无进展提醒；保留版本变化复核、补页和用户要求重审等合理重复。不以固定工具次数截断所有任务、不自动跳过读取。

依赖顺序是任务语义 → 结束/失败交付 → 最小进展与收敛。需要先能正确结束，才能安全地在无进展时收尾。

退出条件：固定审查有明确结论；可控断流/压缩失败后有可理解的部分交付，没有无界重试或副作用重放。

### 5B 后续：按优先级推进三个交互改动

1. **P5-07 工具结果原地展开。** 从 `src/tui/chat-layout.ts` 的短预览和 `src/tui/chat-view.tsx` 的滚动定位入手，以工具调用 ID 管理展开状态。复用 `src/tui/app.tsx` 已接收的工具结果、退出码和日志位置。在视口内按需读取长输出，保留工具区块的阅读锚点。恢复旧会话时，缺少退出码或日志位置的结果按已有数据展示。
2. **P5-08 减少工作区扫描。** 在 `src/agent/delivery.ts` 和 `src/agent/workspace-state.ts` 的观察路径接入现有 metrics，分别记录初始扫描与批次观察的次数和耗时。再于 `src/agent/agent.ts` 的批次执行处，仅对已确认的内置只读工具跳过批次扫描。评估时包含同批工具及相关 Hook 的副作用。编辑、可能写盘的命令、第三方工具和结果未知的操作继续核对，验证通过记录仍须绑定当前改动版本。
3. **P5-09 区分当前补充和下一任务。** 在 `src/tui/app.tsx` 的现有补充队列、提交入口和 `src/tui/input-box.tsx` 的按键处理上增量实现。当前补充在工具批次或模型请求边界消费，下一任务在当前任务正常交付且界面空闲后走普通提交入口，每次只启动一项。失败、取消或权限受阻时暂停队列，用户可撤回编辑或手动提交。队列绑定来源会话，切换会话时待处理内容应可找回。新入口避开已有的 `Alt+Enter` 换行。

三个改动可逐项交付。工具展开与扫描分别完成本地回归，队列改动覆盖任务提交、取消、会话切换和权限边界。对应 S11–S13 纳入 5C 验收。

### 5C：验证能否交付代码

9. 复用既有独立验收器，补真实进程退出/重启与实际 QiCode 任务；验收器不由 Agent 修改，脚本 Provider 与真实模型报告分开。
10. 最后集中核对回复界面、错误状态与实际终端操作，整理本期结果和仍未通过的发布门槛。

退出条件：本期受控任务有独立成功证据；不能只看模型自述、completed 标记或回答长度。

## 固定验收场景

| 场景 | 输入或操作 | 通过标准 |
| --- | --- | --- |

| S12 工作区扫描 | 在带已有未提交改动的隔离副本中分别执行纯读批次、编辑、写盘命令和可能修改文件的 Hook | 单列初始扫描和批次扫描。纯读批次新增扫描为 0。实际写入和验证版本可核对，已有未提交改动不被归为 Agent 修改。 |

- 工具结果用 `Alt+↑/↓` 选择，`Alt+O` 原地展开或收起。命令日志按需读取，`Alt+PgUp/PgDn` 翻日志，`PgUp/PgDn` 滚动对话。
- `/stats` 分别显示初始和批次工作区扫描的次数、耗时。只有执行结果已知的内置纯读批次可跳过观察。配置了可能有副作用的 Hook 时保留批次扫描。
- 运行中按 `Enter` 补充当前任务，按 `Alt+J` 排入下一任务。`Alt+Q` 和 `Alt+U` 分别取回最新补充和最新下一任务。下一任务按入队顺序启动，取消、失败、权限受阻或切换会话时暂停。待处理内容在本次 QiCode 进程内按会话保留。

## 衡量方式

- 先确认正确性与完成情况，再比较速度；失败退出不算更快完成。
- 固定提交、初始副本、模型/端点、thinking、能力、输出预算、授权与缓存条件；不能统一的结果单列，不混成排名。
- 记录用户可见首文本、总耗时、扣除授权等待的有效耗时、主/摘要/后台请求、工具、重复读取、压缩、用量、纠正与接管次数。复用现有 metrics；人工干预先由验收表记录，无法归属的后台请求单列，未知不填 0。
- S01 目标为 0 次工具读取、无需确认；S02/S03 目标为无无关 Git/验证调用、无关键事实错误、一次交付。
- S11/S13 记录展开、阅读定位和队列发送是否符合预期。S12 在相同文件状态和工具序列下对比 Git 扫描次数及耗时，分别报告初始扫描与批次观察。
- 性能目标暂定：S01、S02、S03 分别与各自冻结基线比较中位有效耗时，期望下降至少 25%，不把三个任务混算。正确性与完成率先过门槛；基线没有成功结果时不计算伪“提速比例”，先报告完成率。样本每项三次仅作诊断，不宣称统计显著或通用 SLA；目标在正式对照前冻结，未达到保留失败。
- 真实模型对照先各一次定位，再在条件冻结后各三次；保留全部样本。费用另行授权，不自动接入默认测试，也不代替二期既定发布验收。

## 单人开发与验证约束

按 5A → 5B → 5C 推进，一次只交付一个可检查增量。优先复用现有模块，不先增加模型、Agent 或配置层级。文案、提示词、样式和低风险小改动默认不运行测试、类型检查或构建；关键执行/权限/上下文/存储改动集中做最小相关验证。整期候选再做一次必要整合检查，不在每次编辑后重复全量。
