# 07-Context Start：开发前理解

> 这一页只回答一件事：第七章要解决什么。不要先读实现细节，开发到对应阶段再理解对应代码。

## 本章目标

让 QiCode 可以做更长的任务，而不会因为聊天记录和工具输出越来越多，最终超过模型的上下文上限。

现在的 Agent 每次请求模型时，会把已有会话历史带上。任务越长，历史越大；如果读取了大文件或执行了长命令，一条工具输出也可能非常大。最后模型会拒绝请求：上下文太长。

第七章要让 Agent 在请求模型前，先整理上下文，再发送。

## 最终效果

```text
以前：历史一直累加 -> 模型拒绝：上下文太长

以后：历史变大 -> 先整理旧内容 -> 再继续执行任务
```

整理有两种主要动作：

1. 工具输出太大时，不把全文都塞给模型，而是保存到本地并给模型一个短预览。
2. 聊天历史太长时，把较早的过程整理成摘要，保留最近几轮原文。

## 先记住这一条链

```text
完整会话历史
  -> 准备发给模型的副本
  -> 处理太大的工具输出
  -> 判断是否需要压缩旧历史
  -> 请求模型
```

最重要的一点：完整历史不随便修改。我们只整理“发给模型的副本”。

这样做的好处是：模型上下文变小了，但原始结果仍在，需要时还能继续查。

## 本章不做什么

- 不做长期记忆。
- 不做向量数据库或语义检索。
- 不做跨项目共享历史。
- 不完成恢复旧会话的完整体验，那是第八章的内容。

## 你开始开发前只需要理解

第七章不是让模型更聪明，而是让 Agent 更会“收拾桌面”。

模型每轮只需要看到当前任务最有用的信息；太旧、太大但不能丢的信息，需要先整理或保存到别处。

第一阶段会先做“大工具输出落盘和预览”。完成后，再解释它是如何接入 Agent 的。
